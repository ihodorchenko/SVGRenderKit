# SVGRenderKit — инструкция для агентов и разработчиков

Swift-пакет (iOS): SVG → дерево объектов → `CALayer`. Профиль поддерживаемого SVG и политика
расхождений — в [CONFORMANCE.md](CONFORMANCE.md) (не дублируем здесь), история — в
[CHANGELOG.md](CHANGELOG.md), миграции — в [MIGRATION.md](MIGRATION.md). Язык проекта и общения с
мейнтейнером — русский; комментарии в коде — как есть (английский).

## Тесты

- **Никогда не запускать тесты синхронно в основном потоке/диалоге** — это блокирует сессию. Гонять
  через субагента или в фоне и лишь периодически проверять статус. Субагент возвращает краткий итог:
  число тестов, список упавших, строки крашей.
- Команда: `Scripts/run-tests.sh` — обёртка над `xcodebuild test`. После итога `xcodebuild` нередко
  не завершается сам (Xcode 26/27), поэтому скрипт ждёт строку итога, гасит зависший процесс и сам
  разбирает лог. Вердикт (последняя строка, также в `$LOG.verdict`): `PASSED`, `WARNINGS`, `FAILED`,
  `BUILD-FAILED`, `CRASHED`, `HUNG` (лог не растёт > `STALL_SECONDS`, 180 с), `NO-RESULT`. Код
  возврата 0 только у `PASSED`.
- Аргументы пробрасываются в `xcodebuild`: `Scripts/run-tests.sh -only-testing:SVGRenderKitTests/SVGMemoryManagementTests`.
  Переменные: `LOG`, `DESTINATION` (по умолчанию `platform=iOS Simulator,name=iPhone 17`), `SCHEME`
  (`SVGRenderKit-Package`), `CLEAN=1`.
- Без скрипта: `xcodebuild test -scheme SVGRenderKit-Package -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:SVGRenderKitTests`.
- **Не запускать несколько прогонов параллельно** (в т.ч. из разных worktree на одном симуляторе):
  `xcodebuild` падает/перезапускается, счётчик тестов занижается.
- Инкрементальная сборка иногда оставляет тест-бандл со старыми объектами: падают заведомо живые тесты
  (`SVGStylesTests.testStrokeLinecapParsed` — `nil` вместо значения). Лечится `CLEAN=1`; не искать баг
  в коде, пока не пересобрано начисто.
- Строка `Executed N tests` в логе `xcodebuild` после крэша бывает неполной — не считать её числом
  тестов; смотреть вердикт скрипта и `CRASHED`/`HUNG`.

## Паритет с эталонами

Корпус реальных иконок (`Example/Example/data`) рендерится `SVGView` и сравнивается попиксельно с
двумя оракулами; тест — `SVGRenderParityTests.testCorpusParity`.

- **CoreSVG** (по умолчанию в каждом прогоне): сводка `CORPUS_SUMMARY`. Гейт — `Scripts/check-parity.sh <log> .github/parity-baseline.txt`.
- **Браузер (WKWebView/WebKit)**: сводка `WEBKIT_SUMMARY`. WebKit не стартует в тест-бандле
  (нет entitlement `com.apple.developer.web-browser-engine.*`), поэтому растры дампит Example-приложение
  (`WebKitParityRunner`), а тест их читает. Один прогон обоих оракулов — `Scripts/webkit-parity.sh`
  (build → install → launch → тесты → оба гейта; `SKIP_DUMP=1`, `SKIP_TESTS=1`, `RASTERS=…`).
  Гейт — `.github/webkit-baseline.txt` (`check-parity.sh … WEBKIT_SUMMARY`).
- Baseline-файлы — одна строка сводки: `pass` не должен падать, `fail`/`referenceLimited`/`webkitMissing`
  не должны расти, `kitError` и `referenceMissing` всегда 0. Улучшение → обновить baseline в том же
  коммите; ухудшение → не мержить, а чинить или честно триажить в `ParityTriage` (причина обязательна).
- `reference-limited` — CoreSVG не умеет (`display:none`, `<switch>`, 8-значный hex, смешивание стопов
  в широком пространстве): наш рендер корректен, пиксельного гейта нет.
- Неотслеживаемые локальные папки в `Example/Example/data/*` раздувают `total` корпуса локально — на CI
  `total` другой; сравнивать с baseline по `pass/fail`, а не по `total`, и не коммитить такие папки.
- `.webkit-rasters` (указатель на дамп) — в `.gitignore`, не коммитить.
- Радиальные градиенты в корпусе отсутствуют; их фикстуры `referenceLimited` — геометрию закрепляют
  таргетные тесты. CoreSVG и kit по-разному интерполируют цвет — это расхождение известное.

## Перф

- Гонять только в Release: `-configuration Release ENABLE_TESTABILITY=YES` (Debug нерепрезентативен).
  Сначала профиль/замер, потом правка — оценки «по коду» уже дважды оказывались неверны.
- `.github/perf-baseline.json` берётся **только с CI-раннера** (артефакт `perf.json` зелёного прогона
  `perf.yml` на main), не с ноутбука.
- Гейт `Scripts/perf_report.py` (параметры — в `perf.yml`): тест падает, если медленнее базы > 3×, при
  этом база ≥ 50 мс и абсолютная дельта ≥ 50 мс; тесты с RSD > 35% (в базе или в прогоне) только
  отображаются (`~`). При ложных срабатываниях поднимать `--fail-ratio`/`--min-seconds`, а не отключать.
- Локальные числа сравнивать только перекрёстно: A/B/A/B в одной сессии, `CPU Time`, минимум по 10
  итерациям, плюс контроль, не зависящий от правки (`svgViewCreateAndLayout50`). Одиночные прогоны
  гуляют на ±35% и уже давали ложные «регрессии».
- Offscreen-замеры не описывают экран: `CAGradientLayer` рисует Core Animation, а любой наш CG-слой
  (`RadialGradientLayer`, маски, паттерны) растеризуется в display-фазе приложения.
- Ориентир стоимости на фигуру относительно заливки: stroke ~1.2×, pattern ~1.3×, градиент ~6×,
  clip ~7×, маска ~10×, opacity ~12×. Парс корпуса — доли миллисекунды на иконку.

## Процесс работы над багом

1. Сначала воспроизвести минимальным SVG/тестом — **красный до фикса**. Пункты ревьюеров/аудитов —
   оценки «по коду», не факты; невоспроизводимое закрывать как not-a-bug (с комментарием-инвариантом
   или тестом, если полезно).
2. Фикс минимальный + регрессионный тест; релевантные тесты зелёные.
3. Parity не хуже baseline по обоим оракулам (см. выше).
4. Расхождение «спека/браузер против CoreSVG»: следуем спеке там, где спека и браузер сходятся; CoreSVG
   сохраняем лишь где это заметно лучше на экране. Политика и таблица расхождений — в CONFORMANCE.md.
5. Смена контракта (graceful degradation, публичный API) — запись в CHANGELOG/MIGRATION и явное
   переименование/усиление затронутых тестов (имя теста обязано описывать реальное поведение).
6. Публичный API с опечатками не удаляем, а оставляем `@available(*, deprecated, renamed:)`-шимом.

## Вне скоупа (при встрече — деградируем: пропускаем с логом, не реализуем)

Скрипты/DOM/события; внешние ресурсы (`url(...)` в сеть); `@font-face`/глифы; `@media`; интерактивные
ссылки (`<a>`); полный SMIL (event-`begin`, `additive`, `calcMode`, `fill="freeze"`); `textPath`,
per-glyph списки `x`/`y`; CSS-каскад (специфичность, комбинаторы, псевдоклассы; `inherit` — только для
`visibility`, `clip-rule`, `fill-rule`, `text-anchor`); вложенный `<svg>`; `paint-order`,
`vector-effect`, `non-scaling-stroke`; `overflow`/`<view>`; font-микросвойства, rendering-hints;
`spreadMethod` `reflect`/`repeat` (рендерится как `pad`); относительные единицы `ex`/`rem`/`ch`/`vw`/`vh`/
`vmin`/`vmax` (`em` — для `font-size`, на корне `em`/`auto` → fallback к `viewBox`); полный filter
pipeline (`feMorphology` и пр.). Если реальные иконки начнут это требовать — пересматривать отдельным
решением (в частности `<a>` и вложенный `<svg>` сейчас молча отбрасываются вместе с содержимым).

## Принятые решения и отклонённое

- **Линейный градиент в sRGB отклонён.** Замена `CAGradientLayer` на CG-рисование с sRGB-смешиванием
  (как в браузерах) сближала с браузером (browser fail 79→50), но на экране рисуется заметно медленнее
  даже с `drawsAsynchronously`, а `CAGradientLayer` совпадает с CoreSVG. Остаёмся на `CAGradientLayer`;
  не предлагать заново без способа мерить именно экран (см. P28 ниже).
- **Won't-fix: клип viewport у `<symbol>`** — это `overflow`, он вне скоупа.
- Клип силуэта вместо `mask` у градиента быстрее на 33–42%, но даёт другую AA-кромку — 390 фикстур
  расходятся с обоими оракулами; не делать.
- Сужение окна растра `userSpaceOnUse`-градиента до bbox — до 5× быстрее, но сдвигает AA; держим на
  случай, если станет узким местом.
- `SVGBaseGradient` — поддерживаемая точка расширения (`open`, `public init`); остальные теговые
  классы без доступного снаружи init — `public`, не `open`.
- `spreadMethod` pad-only и смешивание стопов линейного градиента «как CoreSVG» — осознанные расхождения.

## Известные открытые мелочи и отложенное

Делать только при жалобе пользователя или после измерения.

- `<style>` ищется по цепочке предков, а не по всему документу (нужен реестр правил в порядке документа).
- `marker-mid`: на дугах (`A`) возможны лишние mid-вершины; кривые Безье и подпути уже идут по касательным.
- Градиентный/pattern `stroke` на `<text>`/`<tspan>` не поддержан (сплошной stroke, opacity, clip, mask,
  filter — поддержаны).
- `SVGCache.maxCount` фиксирован (100); кэши тайлов/масок ограничены байтовым бюджетом.
- Перф: **P20** кэш результата `SVGRenderer`/растра `SVGView` для списков (меняет публичный API);
  **P25** парс и сборка слоёв на одной serial-очереди, общая мутация `options.renderScale`/`usesPatterns`;
  **P26** градиент/clip без offscreen-`mask` (риск для паритета); **P27** прямой обход модели в
  `CGContext`, байтовый SAX вместо SWXMLHash; **P28** измерение отрисовки на экране (display-фаза
  живого `SVGView`, пропуски кадров при скролле галереи Example); **P19/P21** кэш `path.bounds`/resolved-style,
  `SVGParseD` на сегмент.

## Ловушки

- `style.display != .none` для `SVGDisplaytype?` компилятор молча читает как `!= nil` — сначала
  распаковывать (`if let d = style.display, d == .none` / `switch`); ловится только предупреждением компилятора.
- `parent` у тегов — `unowned`: инвариант «родитель живёт дольше ребёнка» держится деревом;
  нарушение — краш. Не хранить ребёнка/тег вне дерева без владения корнем (есть deinit-тест).
- Тесты через `layer.animation`/`animation(forKey:)` ненадёжны на headless CI; проверять эпоху таймлайна
  `SVGView.animationEpoch` и сэмплировать траекторию.
- Неподдерживаемые единицы в `SVGLength.get` дают `.px(0)`: на корневом `<svg>` это 0×0 — там есть
  fallback к `viewBox`; в других местах учитывать.
- `SVGInputLimits` — потоко-локальные лимиты недоверенного ввода (вложенность 256, `<use>` глубина 10 и
  8192 раскрытий, битмап маски/паттерна 4096 px, `SVGRenderer` > 8192 px бросает, вход 32 МБ, изображение
  64 Мпикс, блюр 500): превышение деградирует (пропуск + лог). Новые рекурсивные обходы (`contentBounds`,
  ссылки mask/pattern/clip/marker/filter) должны уважать guard от самоссылок.
- Маски/паттерны/блюр растрируются в масштабе вывода: документ должен знать, что зависит от масштаба
  (`rendersScaledPaint`), иначе при ресайзе не перерисуется. Parity-харнесс объявляет вывод 1× через
  `SVGView.outputScale`.
- Новое публичное API с опечатками/переименованиями — только через deprecated-шим; тесты шимов держать
  без предупреждений.
- Тесты, закрепляющие баг (старое поведение), надо менять вместе с фиксом, а не обходить.
